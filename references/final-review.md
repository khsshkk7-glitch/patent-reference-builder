# 생성 PDF의 최종 시각 검수

생성 완료, 최종 검수 대기/완료/반려, 자료 유형을 별도로 기록한다. 온라인 수집·공식 로컬 manifest·AI 보완 모두
병합 직후에는 검수 대기다. 조각 PDF 검토는 병합된 결과의 잘림·누락 검토를 대신하지 않는다.
Python은 이미지를 만들고 기록·해시·필수 근거를 검증한다. 이미지 내용을 이해해 이름 오독이나 잘림을 자동 판정하는 기능은 아니다.
현재 작업 중인 Codex 또는 사람이 실제 페이지를 열어 검토한다. 새 AI API 키는 필요 없다.

## 검수 자료 생성

처리결과 JSON 각 생성 행의 `review_packet`에 전용 `final-review.json` 절대 경로가 있다. 같은 실행의 중복 문헌은 이 양식을 공유한다.
PDF의 정확한 경로·해시·전체/서지/원문 페이지 수와 원본 조각 경로·해시가 고정돼 있다.
기본 플래그는 false, 결정은 pending이다. 이전 버전으로 만든 결과에는 필요한 바인딩·보고서 위치가 없으므로 새 버전으로 다시 생성한다.

```sh
python scripts/final_review.py render --packet "/absolute/work/final-review.json"
```

서지 전체 페이지, 원문 첫 페이지 및 끝 페이지를 PNG로 만든다. `images`의 파일을 실제로 열어 인쇄 레이아웃·문헌번호·종별·인명·영문 자료 구분을 확인한다.
검수 양식의 `sections.claims`, `sections.drawings`에 실제 존재 여부 `present`, 구간 시작·끝 등 경계 `pages`, 근거 `note`를 기록한다.
**pages는 병합 결과 PDF의 1부터 시작하는 페이지 번호**이며 서지 페이지 수보다 커야 한다. 한 페이지 구간은 한 번호를 쓴다.
원문에 청구범위나 도면이 없으면 `present=false`, `pages=[]`와 실제 부재를 확인한 근거를 적는다. 필수 자료가 누락된 것을 부재로 승인하지 않는다.

예: 서지 1페이지, 원문 청구범위가 병합본 7~8페이지, 도면이 9페이지부터라면:

```json
"sections": {
  "claims": {"present": true, "pages": [7, 8], "note": "청구범위 시작과 설명/도면 전환을 원문에서 확인"},
  "drawings": {"present": true, "pages": [9], "note": "도면 시작 경계를 원문과 대조"}
}
```

양식을 저장하고 다시 render하면 지정 경계도 렌더링한다. 추가 페이지는 `--pages 7 8 9`로 지정할 수 있다.
렌더링은 결정·검수자·검수 메모·체크를 초기화한다. 모든 필요한 이미지를 만든 **후** 실제로 열어 확인하고 승인 내용을 작성한다.
원문 전체 페이지 수, 청구범위·도면 전체 포함 여부는 공식 뷰어/원본과 대조하며 경계 이미지 몇 장만 보고 전체 포함을 추측하지 않는다.

## 승인 또는 반려

실제 검토가 끝난 항목만 `checks`의 다음 키를 true로 바꾼다.

- `document_identity`: 동일 국가·공보번호·종별과 앞장·원문 일치
- `bibliographic_names`: 발명자·출원인 등 인명과 서지 대조
- `english_material_type`: 공식 영문/사이트 번역/AI 번역/AI 요약/원문 단독 구분·고지 확인
- `full_document`: 전체 페이지와 청구범위·도면 포함 여부 대조
- `layout`: 서지 전체·원문 첫장/끝장·경계 페이지의 잘림·깨짐 확인

`reviewer`에 실제 검수자(예: 현재 Codex), `review_note`에 관찰한 페이지·이름·번호·문제 유무를 적고
`decision=approved`로 저장한다. 의미 없는 true 일괄 변경이나 렌더링만으로 승인하지 않는다.
이름/번호 오독·앞장 잘림·도면 누락 등이 있으면 `decision=rejected`, 검수자와 구체적 반려 사유를 적는다.
자료를 수정한 경우 이전 양식의 해시를 바꿔 재사용하지 않고 새 PDF를 생성해 새 양식으로 검수한다.

```sh
python scripts/final_review.py apply --results "/absolute/처리결과_실행ID.json" --packet "/absolute/work/final-review.json"
```

승인 때 필수 체크·구간 근거·대상 PDF/입력 조각/이미지 해시·필수 이미지가 일치해야 한다.
반려도 대상 파일 바인딩·검수자·사유가 필요하다. 기록한 일시는 적용 시 UTC 시각이다.
새 `검수결과_…xlsx/json`에 모든 원본 행을 보존하고 해당 PDF의 중복 행도 함께 갱신한다.
다음 문헌은 가장 최근 **검수결과 JSON**과 그 짝 XLSX를 입력해 누적한다. 이전 생성 보고서는 당시 검수 대기의 스냅샷으로 보존한다.

승인된 PDF만 새 `검수완료자료_…zip`에 PDF·검수 기록·이미지와 결과표를 넣는다. 완료 ZIP 생성 전 기존 승인 자료도 재검증한다.
반려·미검수 PDF는 완료 ZIP에서 제외한다. ZIP에 결과표가 있어도 표의 실패/반려/대기 행에 해당하는 PDF는 넣지 않는다.
검수자가 원문과 대조한 사실은 기록으로 보존하지만 관청 제출이나 제출 적합성에 관한 법적 판단을 수행하는 것은 아니다.
검수·누적 재개에는 원본 조각과 이미지 파일이 필요하므로 작업 폴더를 보존한다.

공식 자료를 검수 완료했을 때만 `complete_reference=true`다. AI·사이트 번역·원문 단독은 검수 완료해도 이 값이 false이며
`material_type`, 번역 고지와 provenance가 유지된다. `final_review_complete=true`는 이 자료 유형에 따른 최종 검수 완료를 뜻한다.
apply 종료코드는 검수 완료 0, 반려 1, 입력/근거 검증 오류 2다. 생성 명령의 종료코드 0과 혼동하지 않는다.
